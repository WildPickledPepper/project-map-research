## 工具要帮助 AI 理解什么

| 视图 | 内容 |
|---|---|
| 项目地图 | 实际模块、职责依据、语言、入口、构建/部署配置、依赖和覆盖缺口 |
| 代码、接口与数据关系图 | 模块之间的调用、注册、消息、字段、共享状态、资源及连接条件 |
| 运行行为与证据 | 特定版本、环境和输入下的实际路径、状态变化、资源计量和独立断言 |

三个视图应共同服务当前任务：改了哪里、依赖谁、影响谁、哪些条件必须成立、哪些验证已有证据。全项目保持可查询，每次向 AI 返回有关内容及继续展开的入口。该任务组织能力尚未完成整体交付和效果验收。

新增模块、改名和删除应自动发现与更新；业务名称来自源码。未知边界、未支持语言、分析失败和截断需要显式呈现。项目覆盖与单次交互预算分别管理。见[项目无关的自动发现](docs/08-project-independent-discovery.md)。

## 文档检查

Python 3.11 或更新版本，无第三方依赖：

```sh
python scripts/check_research.py
```

检查本地 Markdown 链接及人工案例记录格式，不核验文件哈希，不运行 Insight。源码适配器、原生分析和运行实验按各自报告核验，不能由此检查替代。

## 协作约定

- 优先复用已有解析器、语言服务、构建系统和原生分析引擎，适配明确缺口。
- 每项结论标明实测、源码核对、文档声明、提议或未知；关键关系保留版本、来源和条件。
- 缺边、未解析、未执行和未采集分别表达；运行观测按实际覆盖范围解释。
- 原始 Insight checkout 与 GitCode 上游保持只读。新工具、缓存和实验数据放 D 盘，原始大产物留在 Git 外。
- 完成且验证的成果分别提交和推送，未完成草稿保留其状态。当前功能开发和实验暂停。
