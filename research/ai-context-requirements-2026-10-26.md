# AI 修复 issue 需要什么项目上下文

日期：2026-10-26。对象：多语言、跨进程、强交互、数据密集型应用，当前验收项目为 MindStudio Insight。

本轮核读 9 篇论文的相关方法、结果与限制，并检查 3 个工具的官方交互文档。论文结果标为“作者实验”，工具行为标为“官方文档”；对 Insight 的信息清单和交互设计标为“设计推断”。本轮没有复现论文的模型实验。

## 1. 调研结论

工具应提供任务驱动、分层可查、带源码与运行证据的项目上下文。完整项目模型负责让关系可发现；每轮交互负责提供当前问题所需的事实、关键旁支和继续查询的入口。

应保留三类不同的内容：

1. **当前代码能证明的工程事实**：实体、接口、调用、数据与状态关系、配置条件、构建与测试连接，以及未解析部分。
2. **帮助检索的语义说明**：模块/函数解决什么问题，功能和实现在哪里对应。摘要绑定源码与证据，模型生成的说明标明来源。
3. **当前任务的观测与验证**：预期/实际行为、复现输入、实际运行状态、相关测试与结果、当前排查进展。

现有研究支持搜索、关系导航、语义定位、源码获取和运行反馈的组合；未建立“默认生成并向 AI 提供全仓指令级值流图”优于这些组合的结论。不同信息的作用取决于任务和交互方式，单纯减少 token 也不等于提高正确率。

下列研究大多评估 Python 仓库，或聚焦检索、结构问答等子任务。跨语言协议、共享缓存与资源生命周期的具体清单，属于结合 Insight 场景提出的工程要求，仍需用受控实验检验增益。

## 2. 论文证据

以下数字均为作者报告，保留所读版本、指标和实验条件，不作为本项目已复现结果。

| 来源与版本 | 提供给 AI 的内容及交互 | 作者实验与适用范围 |
|---|---|---|
| [Agentless，2407.01489v1](https://arxiv.org/html/2407.01489v1)，§2.1–2.2 | 先目录/文件结构，再类、函数、字段和签名骨架，最后获取相关实现与邻近上下文；结合现有回归测试过滤补丁 | Python issue 修复流程；支持分层定位与源码展开。该版本主要对完整流程评测，不能将整体表现归因于某一种摘要格式 |
| [RepoGraph，2410.14684v2](https://arxiv.org/html/2410.14684v2)，§3–5 | 代码定义、引用及结构连接，围绕检索位置获取关联上下文 | 接入多种 SWE-bench Lite 修复框架取得提升；作者实验同时显示费用/输入量可能增加。关系图的价值与交互成本要一起评估 |
| [LocAgent，2503.09089v1](https://arxiv.org/html/2503.09089v1)，§3、§5.6、附录 A.1 | 目录、文件、类、函数；包含、导入、调用、继承；SearchEntity、TraverseGraph、RetrieveEntity；折叠/预览/完整源码 | 微调 Qwen-2.5-7B 的消融中，函数 Acc@10 从完整配置 71.53 降到无图遍历 66.06、无 BM25 索引 60.22。最小检索实体为函数；研究范围明确为 Python，不是多语言端到端能力证明 |
| [Code-Craft，2504.08975v1](https://arxiv.org/html/2504.08975v1)，§3、§5–6 | 用 LSP 构图，结合函数源码和被调用者摘要，自底向上生成函数/模块结构化说明用于检索 | 5 仓库、7,531 函数；查询由函数摘要生成。我们的判断：查询与摘要表述接近可能偏向摘要检索，结果不能等同于真实 issue 修复或完整运行依赖恢复。官方完整可执行实现仍未核实 |
| [RPG-Encoder，2602.02084v2](https://arxiv.org/html/2602.02084v2)，§3、§6–7 | 功能语义层与代码依赖层共同组织，功能能定位到源码；SearchNode、FetchNode、ExploreRPG；提交级增量维护 | GPT-4o 消融：函数 Acc@1 完整配置 50.5，去语义层 43.1，去依赖层 44.8；移除语义层同时改变检索和层级导航，不能只归因于“多一句自然语言说明”。93.7% Acc@5 是定位指标 |
| [Evaluating AGENTS.md，2602.11988v3](https://arxiv.org/html/2602.11988v3)，§4、附录 B | 对照无上下文文件、自动生成文件、开发者提交文件；检查说明、工具和测试指引的影响 | SWE-bench 与 Python CTXbench 中，文件没有显著、普遍的成功率增益，平均推理成本增加超过 20%。附录没有发现文件长度与结果的明确关系；不能解释成“文件越短越准确”，也不能据此否定可查询的关系索引 |
| [RIG / SPADE，2601.10112v1](https://arxiv.org/html/2601.10112v1)，§IV–VIII | 构建组件、依赖、启动器、测试、外部包及其构建证据；CMake File API / CTest 提取 | 8 仓库、每仓库 30 个结构问题；7 仓库为合成，非 CMake 图含人工构建。结果支持构建/测试地图的研究价值，不能宣称自动恢复任意多语言项目或证明修复率提升 |
| [Debug2Fix，2602.18571v2](https://arxiv.org/html/2602.18571v2)，§4–6、表 1–2 | 使用调试器回答具体问题：变量/字段值、调用栈、实际分支和执行可达性；将调查结果归纳后返回 | Python SWE-bench-Live 子集上，GPT-5 修复率 31.2%→36.2%，增加 5.0 个百分点；完整运行 token 增加。Java 消融中仅暴露调试工具并不稳定改善结果，收益还取决于编排；这些实验未覆盖 Insight 的 TS/C++/Rust 调试 |
| [RepoAtlas，2609.16936v1](https://arxiv.org/html/2609.16936v1)，§4–5 | 根据 issue 和当前调查状态选择有预算的子图，配合精确符号/源码文本索引；定位、编辑、测试阶段调整视图 | 新预印本：相对多模态基线 SeeRepo，报告平均修复率增加 2.4 个百分点。仅文本/仅图像及固定视图均有退化；静态图漏掉运行时注册依赖的失败案例仍无法定位。说明视图组织的价值，未证明图像对所有模型都有益 |

以下是 2026-10-26 读取的官方文档快照描述，网页会更新；本轮没有安装或复测这些工具，也不把官方效果描述作为受控实验。

| 官方资料 | 可复用的交互思路 | 使用判断 |

| [Serena retrieval](https://github.com/oraios/serena/blob/main/README.md#retrieval)及[工具文档](https://oraios.github.io/serena/01-about/035_tools.html) | 符号概览、符号查找、引用者、声明/实现及诊断；基于现成语言服务或 IDE 能力获取实现 | 适合精确的源码获取与关系导航；不同后端/语言能力有差异。文档中的代理评价不等于独立修复率实验 |

现有工具已经提供了搜索、骨架、符号、源码、预算与分页等成熟能力。优先复用这些接口与组件，适配工作集中在跨边界连接、数据/状态语义和证据组织。

## 4. 面向 Insight 的信息清单

本表为设计推断：由上述证据与当前项目机制共同推导。它规定信息应可获取，不要求每次把所有内容注入模型。

| 信息 | AI 要回答的问题 | 建议呈现与来源 |
|---|---|---|
| 任务和行为差异 | 哪个操作在什么输入/环境下产生什么现象？正确结果是什么？ | 保留用户 issue 原文，结构化复现步骤、预期/实际结果、输入与平台配置；项目图提供可验证事实，缺失预期向任务方澄清 |
| 功能与项目组成 | 这个功能在哪里？有哪些进程、模块、入口和外部依赖？ | 简洁功能说明＋实际模块/构建目标/启动关系＋源码入口；结构信息自动提取，语义说明绑定来源 |
| 代码实体和可用接口 | 已有什么可以复用？准确名称、参数、类型、返回值是什么？ | 符号身份、签名、声明/定义、相关类型与实现；用现成编译器/语言服务获取，按需展开源码 |
| 跨模块连接 | 谁发送、谁接收、在哪里注册、如何分发、结果交给谁？ | 有方向、有条件、有证据的调用、协议/路由、事件/回调、进程/FFI 连接；名称由源码发现，歧义和未匹配端点显式列出 |
| 数据含义和转换 | 输入字段如何变成查询条件？时间、单位、过滤、排序、默认值如何改变结果？ | 关键字段/类型/转换与读写关系，保留与结论相关的实现；一般调用关系不足以回答这些问题 |
| 共享状态和生命周期 | 谁共享缓存或对象？键是什么？何时失效/释放？并发与取消怎样影响消费者？ | 所有者、读写者、键和有效条件、创建/释放及异步边界；遇到别名疑点查询原生分析器，返回明确精度与缺口 |
| 相关实现与既有用法 | 该如何修改？相邻代码采用什么调用方式和错误处理？ | 相关函数本体、调用者/消费者、类型定义和现有用例；摘要帮助定位，源码作为核验依据 |
| 运行观测 | 这次是否经过某个分支？字段、缓存键、对象和请求身份实际是什么？ | 场景/版本/配置对应的追踪、调试器或日志证据；按问题返回关键值、因果链、异常与源码锚点 |
| 验证方法和结果 | 怎样复现、验证修复，并发现对旁支的破坏？ | 可执行的相关构建/测试入口、已有断言、执行状态和错误；区分实际通过、失败、未运行和环境失败 |
| 证据和覆盖状态 | 这个连接可靠吗？查询漏了什么？是否用了旧版本？ | 版本、编译/平台条件、证据锚点、静态候选/运行观察、歧义、未解析、截断和继续查询标识 |

历史事故、历史补丁经验和团队契约仍属于后续独立资产组。本轮不纳入，不改变既定对照实验边界。

缓存的实际内存占用需要运行指标；静态对象/缓存关系只能说明可能的持有与影响。运行轨迹对应具体场景，不能用一次未观察到某条边来证明它永远不会执行。

## 5. 信息如何进入 AI 的工作过程

以下为交互提案，尚未实现或证明能提高 Insight 修复率。

### 5.1 两个独立尺度

- **项目覆盖尺度**：全部适用语言、模块、接口与机制都进入发现和覆盖账；新模块、改名与删除能够更新。不以当前 issue 的相关性过滤项目的存在。
- **当前视图尺度**：每次返回与任务相关的有限内容，保留跨模块连接、关键旁支、未解析端口和展开入口。预算限制呈现量，查询可继续展开。

任何摘要或视图筛选都应保留可回到原始事实与源码的路径。未知边、未分析区和预算截断分别标明；图上没有边不能当作没有影响。

### 5.2 查询应围绕工作问题组织

| 操作意图 | 工具返回什么 |
|---|---|
| 认识项目 | 模块/功能/构建与运行入口、主要连接、覆盖缺口 |
| 从现象找入口 | 搜索名称、文本、功能、错误和协议，返回可核验实体及候选依据；允许从多个入口继续 |
| 追踪关系 | 从实体/接口查询上游、下游、数据/状态依赖与关键旁支，支持方向、关系种类和配置筛选 |
| 阅读与核验 | 获取精确版本的实现、类型、调用位置与连接证据，按需展开、分页 |
| 判断修改影响 | 当前 diff 对接口、数据/状态读写、调用者/消费者和相关测试的影响候选及未解析部分 |
| 回答运行问题 | 给定场景和观察目标，获取实际值、分支、调用栈/因果链及验证结果 |

每项结果包含能继续查询的实体身份、源码位置及版本。面向当前任务的结果再携带适用条件、关键旁支、证据精度与查询范围。共同来源信息集中存储，结果通过引用取得，避免逐边重复。

排查过程中保留已确认事实、未解决问题和反例；编辑改变代码后更新受影响的视图与版本状态。图像视图作为可测试选项，精确符号、关系及源码文本始终可获取。

### 5.3 对计算和存储的要求

默认维护工程级实体、关系和检索索引；深层值流、别名和运行调查作为可查询的证据能力，按问题评估执行范围、预算和缓存复用。

“按需返回”本身不会降低求解器的全程序前置成本。是否能通过现成分析器的摘要、缓存或按需接口降低成本，需要独立执行验证；无法完成的必需语义仍保留为缺口。现有 C++ 全程序 SVF 的资源阻塞没有因本报告消失。

默认上下文不展开：原生临时编号、所有指令级节点、辅助包含边、完整第三方内部图、重复来源字符串、全部原始日志和每个无关引用位置。它们在支持证据核验或深层查询时按需获取；筛选不能损坏跨模块路径，也不能将候选关系表述为已确认事实。

## 6. 怎样验证信息确实有用

以下是后续实验提案，本轮不执行 AI 对照、不打开封存验证样例。样例边界继续遵守[已确认分组](../datasets/msinsight-regressions/split.md)。

各组使用相同模型、issue、源码版本、运行环境和总预算，均保留文件读取、文本搜索、构建与测试能力；变化项仅为新增上下文服务。历史资产全部关闭。

| 组别 | 新增信息 | 用来检验什么 |
|---|---|---|
| B0 | 基础源码/搜索/执行 | 原始能力和成本基线 |
| B1 | 项目/构建地图、符号骨架与精确源码导航 | 入口定位和项目结构是否改善 |
| B2 | B1＋跨模块连接、数据转换与共享状态信息 | 能否找出结构上远离现象的影响、减少误改和回归 |
| B3 | B2＋与任务相关的运行证据 | 对静态不确定性、实际分支和状态问题是否进一步改善 |

这四组先评估成组信息的作用；对确有增益的组再做单项消融。分别比较纯文本与小图＋文本、不同返回预算、是否提供语义说明、不同原生精度/计算成本。避免把模型变化或调试编排变化误算为信息本身的收益。

主要结果由独立复现与回归判定：问题是否修好、是否引入新错误。辅助记录定位召回、关键路径与旁支召回、误连率、证据正确性、遗漏/截断可见性、总 token/调用次数/时间、冷建图与增量更新成本、查询延迟和峰值内存。AI 自评只用于分析，不能单独作为正确性依据。

先确定实验问题和指标，再启动评测；出现负结果按实际报告。完整项目覆盖继续按[既有整体验收](../plans/project-wide-acceptance.md)，不因缩小单轮返回量而缩小分母。

## 7. 本轮交付与执行状态

本轮交付为文献核对、信息清单、交互提案和受控评测建议。没有更换分析引擎、重建大图或改动 Insight 源码；没有修改阶段完成标准。R0/R1 严格状态继续为 partial，原生语义和配置缺口见[已有交付记录](../experiments/2026-10-26-r0-r1/reuse-followup.md)。

实现方向应优先复用已有搜索/符号/源码与图查询接口，把工程级上下文组织清楚，并在开发样例上验证信息增益，再决定深层分析的投入范围。
