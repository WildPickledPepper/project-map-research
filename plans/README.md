# 研究与实施计划 v0.1

日期：2026-10-23。设计依据：[设计基线 v0.1](../docs/05-design-baseline.md)。状态：计划已编写，实施尚未开始。设计基线提交：`547269e`；已有工具试验是输入证据，不代表下列阶段已经完成。

## 要交付什么

围绕 MindStudio Insight 建立可自动更新的项目模型：项目地图、代码/接口/数据关系图、运行行为与证据，并与外部历史问题资产和契约库关联。

首个闭环从 `unit/flows` 开始：正向查询入口到数据处理与结果消费者，反向查询修改影响，关联历史约束，执行正常与迟到响应场景，并明确每项证据的版本和缺口。随后在两条额外真实链路验证规则复用。

## 实施顺序

| 阶段 | 核心工作 | 可检查的交付物 | 进入下一步的门槛 | 规划工作量 |
|---|---|---|---|---|
| P0 设计基线 | 固定范围、资产协作边界、现有证据 | 设计基线和本计划 | 已作为本轮文档成果保存 | 本轮完成 |
| P1 事实层与扩展能力 | 验证 C++/TS 必要符号与候选调用、外部关系导入 | 能力矩阵、统一输入的证据包、底座决策 | 关键 C++ 定义/接口不缺失；证据、作用域、候选及诊断可表达 | 3–5 人日 |
| P2 自定义协议 | 提取两端接口、注册、解码和作用域 | 提供/消费清单、可遍历协议关系、断点清单 | unit/flows 正确匹配；同名不同服务不误连；第二条同机制链无需手写答案 | 3–5 人日 |
| P3 数据、状态与反向查询 | 连接数据库候选、返回字段和消费者，验证一例间接耦合 | 静态链路、反向影响结果、来源与条件 | 首链关键关系可核查；资源读写有作用域；未知明确保留 | 3–6 人日 |
| P4 版本与自动更新 | 先支持可靠全量刷新，条件允许再做增量 | 版本快照、变更差异、故障与一致性报告 | 删除/改值等变更正确，失败不发布成功快照；增量若启用须等价 | 2–4 人日 |
| P5 运行行为 | 接入关键边界，执行正常和项目切换场景 | 可关联 trace、状态事件、环境清单与断言结果 | 在真实 Insight 测试环境验证，能区分响应采用/丢弃 | 4–7 人日 |
| P6 历史资产接入 | 对接外部资产格式、适用性、场景和结果 | 只读适配、关联报告、悬空与过期诊断 | 真实资产往返检索成立，版本适用性明确，原库内容不被修改 | 2–4 人日 |
| P7 地图与 AI 查询验收 | 生成概览、统一查询、复用与任务评估 | 可阅读地图、查询入口、复现指南、发布验收包 | 两条额外真实链路、固定任务集和覆盖报告通过 | 3–5 人日 |

工作量合计 20–36 人日，是研究排程假设，不是完成承诺。假设一名核心实施者，Insight 维护者和资产库维护者按需协作；不含环境、数据和外部接口等待，也不包含全面平台化。P1 后根据实际缺口重估。到达时间盒仍未满足门槛时提交失败证据和选项，不继续无限修补候选工具。

P1 同时确认动态场景环境是否可用；P2 即可开始资产格式对齐；P6 的关联适配可在 P3 后开展，运行结果关联依赖 P5。最终验收等待各必要依赖完成。

## 三个里程碑

| 里程碑 | 范围 | 成功条件 |
|---|---|---|
| M1 可查询静态链 | P1–P3 | 首链正反向贯通，返回字段和候选条件可解释；至少一条额外链验证提取规则复用 |
| M2 可更新与可复现 | P4–P5 | 自动刷新可靠；正常与项目切换运行可叠加到同版本图，独立断言有效 |
| M3 可协作研究原型 | P6–P7 | 历史资产关联、第三条真实链、项目概览和 AI 查询入口一起验收 |

M1 可单独交付并明确标为“静态研究原型”。缺少真实运行或资产对接证据时，不能将 M2/M3 标为完成。

## 当前选型方向

复用语言解析、存储、查询和追踪组件，针对实验已证明的断点补适配。CBM 保留为导航候选；CGC 的更强索引路径待验证；CoderMind 的职责层晚于事实层。CodeGraph/code-map 继续作为接口关联机制的参照，尚无一个通过 Insight 端到端验收。

先用相同输入验证必要能力，再选一个主要底座；仅在明确缺口处组合第二个提取器。首版允许“自动全量重建 + 小型规范化关联层”，不要求立即实现增量、完整 GUI 或全部运行场景。具体取舍和退出条件见 [详细计划书](implementation-plan.md)。

## 怎么审查交付

- 每个阶段有固定输入、提取器版本、执行命令、自动输出、反例和未通过项。
- 人工参考答案用于评分，不能作为提取器输入或手工补边。
- 新增/删除/改名/改值验证关系是否随代码变化；不同服务同名接口验证不会误连。
- 将计划、已执行结果和未知项分开；需要运行环境的验收不能用静态或合成样例代替。
- 当前所有实施验收项均为待执行，具体见 [验收矩阵](acceptance-matrix.md)。
