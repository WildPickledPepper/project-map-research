# 研究与实施计划 v0.1

日期：2026-10-23。设计依据：[设计基线 v0.1](../docs/05-design-baseline.md)，基线提交 `547269e`。**P1–P3 已完成，F01–F05、L01–L06、D01–D05 通过；P4–P7 待实施。** [P2 证据](../experiments/2026-10-23-p2/README.md)覆盖三条真实协议链、改名和作用域反例。 主底座选用 CGC/Kuzu，见 [P1 完成证据与决策](../experiments/2026-10-23-p1-completion/README.md)。

## 要交付什么

围绕 MindStudio Insight 建立可自动更新的项目模型：项目地图、代码/接口/数据关系图、运行行为与证据，并与外部历史问题资产和契约库关联。

首个闭环从 `unit/flows` 开始：正向查询入口到数据处理与结果消费者，反向查询修改影响，关联历史约束，执行正常与迟到响应场景，并明确每项证据的版本和缺口。随后在两条额外真实链路验证规则复用。

规划工作量合计 20–36 人日，按一名核心实施者、Insight 与资产库维护者按需协作估算。范围为研究原型，环境、数据和外部接口等待另计。P1 后根据实际缺口重估；到达阶段时间盒时提交结果与剩余缺口，决定继续适配、更换候选或调整范围。

P1 同时确认动态场景环境是否可用；P2 即可开始资产格式对齐；P6 的关联适配可在 P3 后开展，运行结果关联依赖 P5。最终验收等待各必要依赖完成。

## 三个里程碑

P3 最新验收：**D01–D05 在 154 文件的同一快照通过**，237 项 Python、76 项 TypeScript 测试及存储读回通过。统一查询与源码条件见 [完成报告](../experiments/2026-10-23-p3/completion.md)，第三条跨模块链见 [登记](../cases/memory-usage/README.md)。后续推进 P4 自动刷新，P5–P7 的运行、历史资产与综合验收保持原范围。

| 里程碑 | 范围 | 成功条件 |
|---|---|---|
| M1 可查询静态链 | P1–P3 | 首链正反向贯通，返回字段和候选条件可解释；至少一条额外链验证提取规则复用 |
| M2 可更新与可复现 | P4–P5 | 自动刷新可靠；正常与项目切换运行可叠加到同版本图，独立断言有效 |
| M3 可协作研究原型 | P6–P7 | 历史资产关联、第三条真实链、项目概览和 AI 查询入口一起验收 |

M1 可单独作为“静态研究原型”交付；M2 和 M3 分别以真实运行、真实资产对接及综合验收为完成条件。

P3 早期批次通过所选 140 文件上的 D01 数据库候选与 D04 共享实例检查，114 项 Python 测试及完整图存储生命周期通过。该批 D02 响应数据流、D03 返回字段反查、D05 首链统一说明尚未完成，见 [数据库选择与实例报告](../experiments/2026-10-23-p3/selection.md)。

随后增加 [响应字段生产增量](../experiments/2026-10-23-p3/output-fields.md)：141 文件输入，七处写入可按实参展开到同一响应对象，当时 126 项 Python 测试及存储读回查询通过。

[响应序列化增量](../experiments/2026-10-23-p3/serialization.md) 在同一输入上恢复注册回调和 34 个 JSON 字段/集合路径，当时 142 项 Python 测试及存储读回通过。

[响应对象与路由增量](../experiments/2026-10-23-p3/response-routing.md) 将输入扩展到 148 文件，按参数、模块表和回调注册连接四个发送位置到序列化，并区分生产前后的发送。当时 154 项 Python 测试与存储读回查询通过。

[前端消费与状态增量](../experiments/2026-10-23-p3/frontend-consumers.md) 提取两个入口的 API 返回字段消费、两处连线赋值及四处请求完成后更新。当时 158 项 Python、36 项 TypeScript 测试及完整图存储读回通过。

[响应回调与 Promise 增量](../experiments/2026-10-23-p3/response-callbacks.md) 自动恢复两张回调表、五条交付候选及项目切换筛选条件。当时 162 项 Python、48 项 TypeScript 测试和图存储读回通过。

[请求编号关联增量](../experiments/2026-10-23-p3/request-correlation.md) 将发送字段、请求解码、响应复制和序列化接到前端查找键，覆盖首链四个响应出口。当时 170 项 Python、53 项 TypeScript 测试和存储读回通过。

[C++ 响应发送增量](../experiments/2026-10-23-p3/transmission.md)已将四个响应出口经 JSON 字符串、显式捕获和延迟回调接到 socket 发送参数，得到 12 条带编码分支条件的来源路径。当时 150 文件输入，190 项 Python、53 项 TypeScript 测试及存储读回通过；Windows GBK 转换保留来源缺口。

此前 [socket 接收绑定增量](../experiments/2026-10-23-p3/socket-receivers.md)将原生 socket 创建、发送字段、业务 onmessage 绑定和事件参数连接到响应回调表，组合首链四个后端响应出口及三种 Promise 交付候选。195 项 Python、67 项 TypeScript 测试和存储读回通过。该批保留服务端连接来源与 API 返回关联缺口。

此前 [iframe 返回与 API 解包增量](../experiments/2026-10-23-p3/return-bridge.md)已连接四个响应出口、两处字段状态赋值，并验证两处状态反查和六组断链负例。154 文件输入，223 项 Python、76 项 TypeScript 测试及存储读回通过。该批完成返回关联，随后通过本次 D01–D05 合并验收。

## 当前选型方向

选定 CGC/Kuzu 为主底座，复用 TypeScript 编译器和 Tree-sitter 补齐必要事实。CodeGraph 同一输入对照及 SQLite 扩展维护均已执行，保留为替换方案；CBM 保留导航与更新对照。code-map 的接口机制和 CoderMind 的职责层按相应阶段评估。真实 C++ SCIP 仍为未执行路径；P1 采用有依据的类型候选和显式未知，见 [决策依据](../experiments/2026-10-23-p1-completion/README.md)。

先用相同输入验证必要能力，再选一个主要底座，在明确缺口处组合第二个提取器。首版优先采用“自动全量重建 + 小型规范化关联层”，交付查询入口和两个核心运行场景。增量与交互展示按后续验收结果推进，具体见 [详细计划书](implementation-plan.md)。

## 怎么审查交付

- 每个阶段有固定输入、提取器版本、执行命令、自动输出、反例和未通过项。
- 提取器独立读取源码，人工参考答案仅用于评分。
- 新增/删除/改名/改值验证关系是否随代码变化；不同服务同名接口验证不会误连。
- 分别登记计划、实测结果和未知项；运行验收在真实 Insight 环境执行。
- F01–F05 已在固定 65 文件、共用样例和两种数据库范围通过；协议、数据流、自动更新、运行和资产接入按后续门槛验收，见 [验收矩阵](acceptance-matrix.md)。
