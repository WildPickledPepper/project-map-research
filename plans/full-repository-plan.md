# 下一阶段：全仓自动发现与覆盖扩展

日期：2026-10-24。状态：**规划，尚未实施**。本计划承接 [P7 验收](../experiments/2026-10-24-p7/completion.md)，按[能力架构与覆盖矩阵](../docs/06-capability-coverage.md)安排下一阶段工作。

## 目标与当前起点

把经过案例验证的原型推进为无需人工挑选业务文件、能够自动发现全仓模块与接口，并支持关系展开的项目理解工具。

P7 已枚举 Insight 固定提交中的 4,855 个受版本控制文件，语义图仍使用选定的 191 个输入文件。其三条协议链和两条返回字段链构成回归基准。下一阶段首先扩大 TS/TSX、C++ 及头文件的事实提取范围，同时保留其他语言和机制的覆盖状态。上述数字为 P7 实测起点，新版本按实际源码重新统计。

首项交付是：从仓库和构建清单自动确定 TS/C++ 分析范围，使新增模块、源文件、接口声明和注册点进入分析流程。输入配置描述语言、构建变体、排除规则和机制适配；业务文件选择、具体接口名称和目标 handler 由程序从源码提取。

## 工作顺序与交付

| 顺序 | 工作 | 交付 | 完成标准 |
|---|---|---|---|
| A1 全仓自动发现 | 枚举路径、语言、包、构建信息、入口、接口、注册点与资源候选；自动生成分析输入 | 文件/模块清单、输入生成器、覆盖报告及排除依据 | 固定业务切片退出常规输入流程；新模块和接口可发现；每个文件都有处理状态 |
| A2 确定性连接扩展 | 扩大 TS/C++ 符号与调用分析，连接协议、字段和资源读写 | 版本化事实图、接口两端清单、条件与缺口 | 身份和连接从源码恢复；名称变化跟随源码；歧义、动态值与缺失上下文有诊断 |
| A3 可展开地图 | 基于同一事实集生成全仓概览，支持入口正查、符号/资源反查和按需展开 | 概览与查询入口、分页和预算控制、源码导航 | 从任意已发现入口可查询分析状态、已有关系及断点；大结果能够逐层读取 |
| A4 留出与更新验收 | 冻结规则，在此前未参与适配的模块/链上执行；检查新版本变更 | 首次结果、独立参考、误连/遗漏分析和更新报告 | 首次失败保留；自动恢复、错误连接、遗漏与未知分别统计；新增、改名、删除反例成立 |
| A5 运行验证扩展 | 对新链的重要分支采集执行与状态变化，建立独立断言 | 场景、运行记录、静态映射和断言结果 | 验证实际实现选择、缓存命中与状态采用；并发和资源结论有相应观察证据 |

A1 先实施，A2 随发现结果扩展，A3 随事实层交付。A4 的评估协议和参考在对应留出实验前冻结；A5 按新链的重要行为开展。

历史问题样本按用户确认的[样本划分 v1](../datasets/msinsight-regressions/split.md)执行：当前仅用 8 条开发样本驱动适配和复现，4 条关联回归不计独立验证，12 条验证候选暂不开展定向研究、执行或调规则。A4 的历史样本验证部分等待用户启动；A1 的全仓自动发现及通用事实提取继续按构建范围开展。

## A1：第一批具体任务

1. 读取全仓受版本控制路径、包清单、tsconfig 与 CMake 等构建信息，建立可重现的输入发现流程。
2. 自动纳入范围内的 TS/TSX、C++ 和头文件，分类标注产品、测试、构建工具及第三方/生成内容；每项排除保留理由。
3. 复用现有提取器和规范化模型生成符号、接口声明、注册点及其来源。词法候选与已解析语义事实分别记录。
4. 对读取失败、解析失败、缺编译上下文、不支持语言和执行预算中断输出结构化状态，保留可继续处理的任务。
5. 在独立测试副本新增模块/文件及接口，验证发现流程自动纳入；继续运行既有三条链的回归。

这一批先报告范围发现和事实提取结果。跨语言边界连接、字段传播与运行行为按 A2–A5 分别验收。

## 复用与适配原则

继续复用已验证的 CGC/Kuzu、TypeScript 编译器、Tree-sitter 与现有适配器。依据全仓结果记录具体能力或成本缺口，再决定引入已有实现还是新增机制规则；沿用[工具调查](../research/tools.md)中各工具的固定版本和证据等级。

新增规则描述语法结构、框架机制、接口身份与作用域。跨边界连接独立提取消费方、提供方及匹配条件；运行部署、构建变体或外部配置缺失时，明确列出需要的上下文。业务名称只用于独立评分和回归案例。

全仓概览用于定位，详细调用和数据关系按查询展开。展开深度、分页、时间与内存预算必须可见，便于区分范围限制、执行中断和真实失配。

## 验收矩阵

| ID | 检查 | 预期证据 |
|---|---|---|
| W01 | 从固定源码自动生成输入 | 受版本控制文件数、各语言/分类数量、纳入/排除清单及原因；无需填写业务文件列表 |
| W02 | 新增模块、文件、接口和注册点 | 下一次分析自动发现，并显示提取、匹配或未知状态 |
| W03 | 接口/符号改名与命令改值 | 新身份及关系随源码重算；旧引用清理或明确失效 |
| W04 | 删除注册或提供方 | 旧连接失效，消费者报告未匹配；其他作用域的同名接口不被替代连接 |
| W05 | 全仓处理失败与预算中断 | 未处理、读取/解析失败和不支持项均进入覆盖报告，已完成范围可核查 |
| W06 | 关系与查询 | 关键边有源码、规则和版本；正反向查询保留条件、歧义及展开截断 |
| W07 | 新模块留出链 | 提取前冻结规则/输入/评分标准；保留首轮输出；人工参考只用于评分 |
| W08 | 独立重建与变更维护 | 新输出目录重建可比较；新增、改名、删除及跨文件失效后，关系与源码一致 |
| W09 | 新链运行与状态断言 | 记录实际分支及状态采用；用正常/异常对照验证断言；运行关联到对应静态版本 |
| W10 | 缓存、并发和资源行为 | 根据目标场景观测命中/未命中、交错或资源指标；逻辑清理、容量和实际占用分别报告 |

覆盖报告分别给出文件发现、事实提取、接口匹配、字段链、场景执行和断言覆盖。分母来自当前版本清单或预先冻结的参考范围；解析成功数量与图规模不作为全仓语义正确率。

留出评估同时检查完整路径、错误连接、遗漏与已识别未知。若采用智能体测试，使用独立目录和隔离指令，评分材料不入输入包，首次答案与错误保留。共享文件系统的实际隔离方式沿用 P7 的公开说明。

## 与 P6、P7 的关系及实验约定

P7 已完成的独立范围继续作为历史基准，不因本计划调整而改写结果。P6 在资产维护方提供真实样例后可并行接入，M3 联合验收仍依赖真实资产。

所有源代码变更实验和运行埋点使用独立副本。研究 GitHub 仓库保存工具、计划、公开样例和紧凑证据；原 GitCode 仓库及原下载副本保持不变。版本通过 Git 提交与工具版本记录，按用户偏好不重新核验文件哈希。

本次提交保存后续目标、执行顺序和验收约定；实施结果将在对应实验中独立记录。
