# A5 运行验证执行计划

日期：2026-10-25。状态：环境准备。静态扩展见 [异步与分页实验](../experiments/2026-10-25-static-async/README.md)。

## 目标

把选定新链的实际请求、处理器、数据来源、返回采用及 Worker 转交映射到对应版本的静态图，附场景断言。沿用 P5 的运行身份关联、不可变记录与故障对照。

## 执行顺序

1. 准备独立运行副本，确认后端、Framework、Cluster、Leaks、浏览器及公开样例。记录源码提交、构建输入与运行配置；新采集改动提交到禁用推送的实验副本后，重建涉及组件。
2. 先运行通信迭代查询：从公开集群样例独立读取预期迭代，操作界面触发请求，采集防抖调度、请求身份、实际 handler/数据库目标、返回字段与最终消费者。
3. 运行分页 blocks：确定可被当前导入器接受的公开 snapshot 输入，独立计算分页总量与期望块集合，观测每页、合并、Worker 消息及采用的 generation。现有 leaks dump 只作为 memscope 输入候选，需另外验证 snapshot 输入。
4. 增加异常、切换与并发：覆盖延迟返回、请求失败、取消/替换、项目或设备切换、交错分页；记录每个请求的成功、失败、丢弃或仍待返回状态。
5. 采集缓存未命中、命中、失效与重建。分别记录缓存条目、逻辑容量、ArrayBuffer/JS heap 与进程指标；每项结论标明采集范围。
6. 加入受控故障对照，确认独立断言确实能识别错误结果或跨上下文采用。恢复正常实现后重跑相同场景。
7. 将运行记录映射至同源码、同构建及同配置图。保留未映射事件、采集缺口、断言失败和跨版本拒绝结果。

## 验收

| 范围 | 要交付的证据 |
|---|---|
| 正常链路 | 交互、请求、实际后端实现、响应、消费/Worker 身份可关联；独立输入断言通过 |
| 调度与并发 | 迟到响应、替换和交错场景有请求处置及状态采用记录 |
| 缓存与资源 | 命中/失效有事件；内存结论有相应观测；逻辑清理、容量与实际占用分别列出 |
| 断言有效性 | 正常实现通过，受控故障触发预先定义的失败，恢复后再次通过 |
| 图与运行 | 同版本映射可查询，未映射与采集缺口可见，跨版本验证结果保持独立 |

本阶段先执行上述新链与关键分支；场景清单在运行前冻结。历史问题契约库由 P6 接入，原历史样本集合归属保持不变。静态候选、环境准备和真实产品场景分别统计。
