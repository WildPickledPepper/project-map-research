## 1. 交付目标

为指定代码版本自动生成可供 AI 查询的三个视图：

| 视图 | 本项目应交付的内容 |
|---|---|
| 项目地图 | 全部自有运行模块、职责及源码依据、入口/出口、依赖、构建与部署条件；可从逻辑模块展开到文件与符号 |
| 代码、接口与数据图 | 各语言内部的定义/引用/调用；模块之间的协议、注册、事件、进程和文件连接；参数、返回字段、数据库、缓存、状态及展示依赖；支持正向和反向查询 |
| 运行行为与证据 | 核心工作流的实际分派、身份与因果、异步处置、状态变化、资源生命周期和独立断言；关联同版本静态图 |

AI 从 issue 的现象、触发条件和复现输入出发，可以找到入口，展开跨模块链，核查源码与运行证据，并追查共同消费者。skill 是操作入口，确定性事实由工具提取。

完成标准以逻辑运行模块和跨模块机制为单位。文件被枚举、语言 parser 可用、节点变多、局部链通过、测试数量增加和安装成功，各自保留原含义。

**工具引擎项目无关，Insight 是本轮验收对象。** 生产输入为源码、构建/部署上下文及通用分析策略；模块名称、接口名称和新增模块清单从源码发现，不作为提取器白名单。账本是某个版本的输出和验收快照。新增模块自动进入发现、提取、连接、刷新与覆盖检查；新增未支持语言/机制自动形成必需缺项。跨项目验收使用不同项目名称、目录结构和模块增删改名，复用同一套规则。

## 3. 范围与模块责任

### 3.1 必需范围

全部第一方运行代码进入语言事实提取；影响运行的构建、配置、样式和资源进入相应依赖分析。第三方库保留版本、所用 API 和交互边界；第三方内部实现按具体分析需求展开。生成内容必须关联生成来源；缺少生成输入时登记依赖问题。

测试、构建工具、产品代码分别标角色。测试保留测试目标关系，构建脚本保留产物/配置/进程关系，不能把所有脚本归为产品运行模块，也不能因其是脚本而忽略对产品的影响。

### 3.2 已知模块组及必须展开的关系

本表为已知范围下限。W0 从已有全仓清单、源码入口和注册点自动生成实际模块账本，逐项核对。新增发现增加账本条目，不删除已知组。

| 模块组 | 已知路径或组成 | 要纳入的关系 |
|---|---|---|
| 前端业务模块 | `modules/cluster`、`compute`、`leaks`、`memory`、`memory-on-chip`、`numa`、`operator`、`reinforcement-learning`、`statistic`、`timeline` | UI 入口、请求、返回值、状态、事件、消费者、组件/样式依赖 |
| 前端公共层 | `modules/framework`、`modules/lib` 和公共构建入口 | 窗口/iframe 通信、公共请求与连接、共享组件、公共状态、包导出 |
| 后台执行 | 各模块中的 Worker、后台任务、调度器 | 创建、消息、任务身份、转交对象、取消/替换、清理及结果采用 |
| C++ 服务 | `server/msinsight`、`server/src/entry`、`server/src` 中的协议、服务、模块、解析与数据库层 | 启动、配置、模块和 handler 注册、实现选择、数据导入、查询与响应 |
| 平台层 | `platform` 及其平台/feature 条件 | Rust 入口、后端进程、端口、HTTP/资源服务、WebView、前端加载、退出和回收 |

各组进一步拆分为可独立查询的逻辑模块。归属规则来自 package/构建目标、导出、入口、注册和依赖；相互引用由图连接，具体业务名称不进入匹配规则。

### 3.3 动态关系的处理

每个已发现边界必须落到以下一种有依据的状态：确定连接、有条件候选、未匹配、解析失败、需要运行上下文、经源码核对不属于连接。记录两端、表达式、候选、条件和下一步所缺信息。

不可静态唯一确定的关系保留条件和候选，并用对应运行场景核查实际目标。整种第一方运行语言没有事实提取、某运行模块只有文件清单、某个实际使用的边界家族完全没有适配，均阻止整体完成。局部残余动态未知允许存在，但必须定位到具体位置、限制影响结论，并符合验收矩阵的处理要求。

保留现有图模型、版本控制器、数据存储、导航索引和记录 API。新语言和机制通过统一事实接口接入；生产提取不读取人工参考或 issue 修复答案。

| JavaScript | TypeScript 5.9.3 编译器及已有 TS 分析流水线 | JS/JSX/MJS/CJS 输入、ESM/CommonJS、混合 JS/TS、包 exports 和分析配置；先验证再启用 |
| Python | CGC/Tree-sitter 现成解析；需要结构补充时使用与项目语法兼容的 Python AST | 包与相对导入、别名、实例/方法、异步与回调、装饰注册、进程和网络参数的值来源 |

| 协议、数据与状态 | 既有 TS/C++ 值来源、注册、字段、回调、传输与返回适配 | 将机制扩为语言无关的提供/消费描述，增加进程、文件、插件等接入规则 |
| 配置/SQL/样式 | 对应现成解析器、构建清单及既有资源模型 | 先记录现有可复用组件和版本，验证项目实际写法，再补缺失的语义关联 |

固定组件起点：CGC `93c9685bff9151f50a3121e9913e5ba2d27c1191`、TypeScript `5.9.3`、Tree-sitter `0.25.2`、language-pack `1.20.0`、Kuzu `0.11.3`。这些版本曾参与既有实验，不代表新增语言已通过；实际采用和升级决定保存到 W0/W1 结果。

官方能力依据：TypeScript 的 [allowJs](https://www.typescriptlang.org/tsconfig/allowJs.html)允许 JS 与 TS 共存；Python [AST](https://docs.python.org/3.11/library/ast.html)提供语法树；[Tree-sitter](https://tree-sitter.github.io/tree-sitter/)提供语言语法树及 Python/Rust/JS 等 grammar。以上是解析能力，跨文件调用及项目接口连接由 W1/W2 的实测验证。固定版本选型依据见 [P1 决策](../experiments/2026-10-23-p1-completion/README.md)。

## 5. 实施顺序与工作包

依赖顺序：**W0 → W1 → W2 → W3 → W4 → W5 → W6 → W7**。W1 每接入一种语言就同时打通一个实际跨模块边界；W2/W3 的相应运行采集可提前准备，整体状态仍按门槛计算。W5 的覆盖状态接口从 W0 开始接入，最终在 W5 完成独立交付验证。

### W0：冻结全项目模块、边界和验收分母

输入：既有全仓清单、结构地图、能力矩阵、各构建/运行入口、旧 P/A 证据。

工作：

1. 把所有跟踪路径映射为逻辑运行模块、构建/测试支持或外部依赖，拆开根目录和 `server/src` 的粗粒度归属。记录自动归属依据及冲突。
2. 为每个运行模块登记入口、导出、注册、外部交互、持有数据、配置、上/下游、运行模式及现有提取状态。
3. 对照 18 类机制生成“模块 × 机制 × 证据”账本；检查 JS/Python/Rust、插件、构建、资源/样式和后台入口是否漏项。
4. 从官方支持的启动方式和配置形成平台/feature/本地/代理/插件模式矩阵；实际不存在的组合用源码依据排除，环境尚不具备的组合列入环境任务。
5. 为每类接口选取独立源码参考、正常/负例和运行验证方式。优先使用新的通用 fixture 与模块接口审计，遵守现有样本用途约定。
6. 冻结必需项与验收 ID、当前状态、证据来源、排除依据和分母修订规则。

交付：`module-inventory.json`、`boundary-inventory.json`、`mechanism-matrix.json`、`runtime-modes.json`、基线覆盖报告及参考评测包。已由自动发现规则 `a328dcd`、独立参考/审计 `8c2f114` 完成正式冻结，388 项范围检查及 7 个冻结故障控制通过，G01 通过。124 个运行/库与 5 个支持组件、18 类机制、19 项边界/接口参考、85 项运行义务及依赖缺口进入后续门槛。

门槛：整体验收矩阵 G01。本阶段完成的是分母和执行任务；其他语言与模块缺口仍保持未完成，不借清单完成推进整体状态。

### W1：多语言事实接入与第一条真实连接

实施顺序为 JS 混合模块、Python 代理/插件、Rust 平台层；三个适配均为必需。

当前进度：JS 基础事实和首条混合模块链已验证；[Python 基础事实、首条代理接口链与安装更新](../experiments/2026-10-25-w1/python.md)已验证，119 文件全仓复验通过。Rust 统一事实、平台接口与安装更新也已有实测结果；[同一默认全仓快照复验已通过](../experiments/2026-10-25-w1/repository-recheck.md)，跨进程对端和完整模块机制继续按 W2–W5 展开，G02 保持未通过。

Rust 的[原版组件、Cargo 上下文、统一图及独立安装](../experiments/2026-10-25-w1/rust.md)已有实测结果：13 文件入图，24 个配置上下文、41 项生产图查询和 22 项安装/模块更新检查通过。全部语言默认全仓重建及后置语言评分已通过；进程到后端的产物/实例配对继续按 W2 展开，G02 保持未通过。skill 统一整理和打包安排在工具能力及验收稳定后。

1. 在相同源码上运行现成提取组件，记录各自保留的身份、引用、导入与调用。将可复用输出接入统一 schema，保存上游版本及归一化规则。
2. JS 支持模块加载、导出与重导出、CommonJS、JS/TS 混合调用和构建配置的引用。Python 支持包/别名、类实例、函数/异步调用、回调/装饰注册及参数来源。Rust 支持 module/use、impl/trait 候选、闭包、feature/OS 条件和边界参数。
3. 每个符号使用语言、模块、声明位置和作用域形成身份。调用点保留静态目标、条件候选或具体未解析原因。
4. 同批验证 JS→TS 使用、Python 代理消费/提供边界、Rust 启动后端边界，防止新增语言再次成为孤立小图。
5. 接入自动发现、输入导出、刷新、统一搜索、源码导航及图遍历；删除和改名后清理旧实体/连接。

### W2：连接全部运行模块与跨模块边界
