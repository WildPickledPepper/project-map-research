### R0 固定准入题

仅对未验证扩展和替代缺口能力执行；已完成的相同输入/版本试验直接引用。首次运行前冻结题目和预期。输入使用通用 fixture、普通源码及 W0 独立接口参考，不使用历史验证题或修复答案。

| 组 | 必查问题 |
|---|---|
| C++ 语义 | 类外定义、继承/重载、别名/模板、条件编译；getter 的值/引用/指针返回；原生来源位置和编译上下文 |
| 数据流 | 跨函数实参/形参和返回、分支、成员写读；两个同类实例及复制/借用；外部方法默认语义造成的额外候选 |
| 现有语言复用 | 继承 TS 导入/回调、Python/Jedi、Rust/RA 的现有收据；只有导入契约变化才复验受影响项，不重新做完整选型 |
| Rust 新引擎 | 分发包 rust2cpg 是否可用、能输出哪些事实/依赖；未通过则保留 RA，明确数据流缺口，不自行写通用替代 |
| SQL | SQLite SELECT/JOIN/别名/CTE/参数的可用解析和血缘；数据库实例隔离由宿主适配单独核查 |
| 跨项目 | 至少两个不同布局 fixture，模块新增/改名/删除；无需修改业务名称规则 |
| 导入可用性 | 输出能携带原生 ID、位置、配置、条件/精度导入统一图；原生候选不能被升级成精确别名或实际执行 |

每组既有正例也有隔离/歧义负例。准入失败应给出原始输出、缺的能力及影响范围；“工具运行成功”“图非空”不算该能力通过。R0 可以确认某个候选不可用，该结论终止该候选的集成，不授权重写其引擎。

## 4. 防止单点无限扩展的执行规则

1. **R0 首轮预算**：主动安装/调试/适配累计最多 2 小时，每个新候选最多 45 分钟；下载/运行等待单列，首轮总墙钟上限 3 小时。上限触发即交付已取得结果和明确失败，停止该候选，不转为自研。预算是复盘触发器，不是承诺三小时通过全部准入。
2. **后续按批交付**：每批主动实现/分析最多 90 分钟，同一局部链最多 30 分钟。到限即提交通过部分、首轮失败、全分母变化和下一技术选择；最多一次有明确修复假设的复验，继续失败则停止该支线，推进其它独立批次。
3. **每个失败有出口**：只允许修正调用/配置、补一个有限 API 模型、启用已列备选，或登记外部依赖/能力阻塞。新增通用求解算法不属于默认出口。若仍阻断必需链，阶段/整体保持未通过。
4. **每个进程有期限**：启动前记录命令、输入、输出、句柄和截止时间；工具调用分段返回。超时先检查已有进程，禁止反复启动重复全仓任务；长任务保持状态更新。
5. **复用结果，减少重复成本**：同输入和提供方版本复用原生事实；相关机制定向检查先行，只有共享语义/发布接口有实质变化时才跑完整回归；每阶段最终做一次同版本全仓核验。参考答案始终在提取后评分。
6. **完成一项即提交并推送**：紧凑提交区分提供方接入、机制模型和真实全仓证据；不会把每个字符串/语法小变体都包装成新的阶段完成。
7. **进度按分母报告**：报告已验收组件/129、独立参考/19、适用机制项、运行义务/85及误连/阻塞；分母有变化说明依据。节点数和单测数量只作补充。

阶段失败后可继续独立工作，不能宣称相应 G 门槛通过。预算用完也不能自动缩范围或把缺项改为不适用。首轮完整评估结束后应有一份有限的决策清单，而不是一条持续加深的局部链。

## 5. 各阶段统一验收收据

使用现有研究收据/证据格式，至少包含：

- 产品源码与提供方/规则版本、配置和输入；原生执行还是缓存导入。
- 能力/模块/边界责任、复用组件、接入文件及旧实现保留/替换情况。
- 冻结预期、实际结果、正反例、首次失败与复验，逐项通过或阻塞依据。
- 全分母中本批完成项、剩余项和整体门槛状态；下一批及其依赖。
- 下载/环境、原生分析、适配、验证和查询的分项耗时；命令及终态。

自写适配的准入条件是：原生输出已核查、缺口属于边界/模型/互操作、存在独立正反例，并能限定输入输出。无法满足时先给出技术决策，停止继续堆代码。
