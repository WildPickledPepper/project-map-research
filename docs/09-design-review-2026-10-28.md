# 设计复盘：让 AI 看见一次修改需要满足的条件

日期：2026-10-28。状态：讨论整理；功能开发、原生分析和 AI 评测继续暂停。本次交付为文档，不改变既有验收结论。

## 1. 原始目标与这次确认的遗漏

本工具面向多语言、跨进程、强交互、数据密集型的桌面/Web 应用，首个验收对象是 MindStudio Insight。目标是帮助 AI 理解整个项目，定位 issue，并识别一次修改对其他模块、数据、状态、资源和运行条件的影响。新增模块、改名和删除应由工具自动发现与更新。

此前实现主要围绕文件发现、语言事实、关系边、局部链路和组件准入推进。实际默认了一个假设：AI 查到图后，会自行找出与这次修改有关的前提、旁支影响和验证要求。这个假设将用户希望工具帮助解决的困难继续留给了 AI。

**设计和执行上的遗漏，是没有把“针对当前任务组织修改依赖、成立条件和验证证据”作为实际交付与验收的主线。** 旧计划已经写过 issue/diff 上下文，相关研究也列过信息需求；这些文字尚未落实为经验证的默认使用过程。定位命中、节点增加和局部测试通过，回答不了 AI 是否因此少引入了新的问题。

本轮复盘先澄清工具应提供的信息、已有能力及证据缺口。后续实施顺序需要在此基础上核对。

## 2. 三个视图怎样服务一次修改

原有三个视图继续承担基础职责：

| 视图 | 应提供的信息 | 用于当前任务时需要回答的问题 |
|---|---|---|
| 项目地图 | 实际模块、职责依据、入口、语言、构建/部署配置、依赖及覆盖缺口 | 这次问题或修改涉及哪些模块，还有哪些关联模块需要展开？ |
| 代码、接口与数据关系图 | 调用、注册、消息、字段、读写、共享资源和有条件的连接 | 哪些生产者、消费者和共享状态依赖这里？连接在什么身份、配置与时序条件下成立？ |
| 运行行为与证据 | 实际场景、执行顺序、状态变化、资源计量、结果与独立断言 | 哪些条件和行为已经在匹配版本及环境验证？哪些仍未验证？ |

“针对修改组织信息”是三个视图的使用要求。全项目保持可查询；每次交互优先返回当前任务有关的关系、条件和证据入口，并允许继续展开。呈现预算与项目覆盖分别管理，未解析区域仍需可见。

## 3. 应向 AI 提供什么

下表是本次讨论形成的信息要求，**属于设计要求，尚未完成整体实现与效果验收**。

| 信息 | 最少需要包含的内容 | 自动化依据与未知项的处理 |
|---|---|---|
| 当前任务和变化 | issue 原文、预期/实际现象、复现条件；方案或 diff；新增、删除和改变的行为 | 保留任务原文和 Git 变更。新文件、新调用及新平台依赖也要进入分析，不能只查旧图已有节点 |
| 依赖和影响对象 | 直接/间接消费者、共享数据和资源、接口字段、参数/返回值、事件和状态关系 | 复用语言/构建事实和机制适配；每项给方向、身份、源码位置及解析状态，缺边显示未知 |
| 关系成立的条件 | 平台/编译器/标准库、构建配置、数据源与对象身份、生命周期、先后顺序、单位与精度 | 条件绑定来源和配置；源码守卫、类型事实、任务要求与人工契约分别标明。未恢复的业务前提保留为待确认 |
| 变化前后的差异 | 哪些依赖、调用方式、类型、适用范围或副作用发生变化，未改动的消费者是否受影响 | 比较基线和候选事实；未提交 diff 单独读取，不能标成已进入旧快照 |
| 验证证据和缺口 | 对应版本、环境、输入、场景、执行命令、断言与通过/失败/未执行状态 | 复用实际构建、测试及运行记录；将具体缺失条件交给 AI 继续调查，证据的适用范围随结果返回 |

依赖包括调用、数据、状态、资源和环境条件。例如“返回值类型依赖标准库配置”与“两个函数存在调用关系”表达的是不同事实；条件信息需要保留其含义。

工具提供可检查的事实和未解决问题，AI 据此提出风险假设、读取源码和实施修改。正确性由任务预期、独立断言、编译和运行验证共同判断。自动生成的业务解释要附来源与核验状态。

## 4. Issue #655 实验说明了什么

证据类型：已执行实验及记录审查。源码基线为 `207a0928b5ff8d10aaca6bb4a492750508099e94`，参与者候选为 `67b25fae80461cc6231316e805f6e6ce10634d77`。完整过程见[实验报告](../experiments/2026-10-28-issue655-full-assets/README.md)、[参与者交付与验收记录](../experiments/2026-10-28-issue655-full-assets/participant-validation.md)和[探针结果](../experiments/2026-10-28-issue655-full-assets/clock-probe-results.json)。

参与者能够访问完整历史资产，实际阅读了总规则及若干相关条目。C++ 23 项和前端 28 项自测通过。新增缓存版本代码把文件时间的计数直接写入字符串流；实际生产翻译单元在原生时钟类型下编译通过，在受控 `__int128` 时钟计数类型下出现 `operator<<` 重载歧义。

这是受控类型兼容检查，原生 macOS SDK 编译仍未执行。正常 MinGW 最终链接另因重复 `__stack_chk_fail` 失败，使用本地临时链接选项后完成链接。真实 profiling 导入、桌面交互和完整目标平台验收仍缺证据。自测通过应按其实际检查范围解释。

历史规则 R05 涉及 SQLite 的零字面量重载及 Apple Clang 检查，是相关的平台兼容风险类别，与这次文件时钟代码的具体 API 不同。轨迹没有显示参与者展开 R05 详细证据或执行 macOS 编译。该实验提供了“资产可访问且部分被使用，新增代码仍漏检”的实例；它没有同题源码组或项目地图组，无法据此估计历史资产或项目地图的净收益。

### 应怎样帮助模型自己发现问题

下面是期望的信息组织示例，证据依据来自本次事后审查，**当前工具尚未对该候选自动生成并验证这份结果**：

```text
新增缓存版本计算
  → 数据库/WAL 文件状态
  → 文件时间 → duration 计数类型 → 字符串流输出
  → 缓存身份与失效判断

需要核对：目标构建配置中的类型和输出兼容性
已有证据：当前环境的原生类型编译通过；指定自测通过
缺失证据：其他受支持目标配置的类型/编译检查及完整场景验收
```

在实际协作输入中，应提供源码可见的依赖和证据缺口，让 AI 判断是否需要调查目标平台类型。后续评测时，受控探针结果及修复答案由评分方持有，不能作为提前提示输入。

新实现产生的依赖可能不存在于基线图。只查询旧调用者无法审查新增文件、标准库调用和环境前提；基线地图需要结合当前 diff 与候选事实使用。

## 6. 分析预算与 AI 交互预算

现有成本证据见[原生预算报告](../experiments/2026-10-26-native-budget/completion.md)、[Rust Debug 捕获](../experiments/2026-10-26-native-budget/rust-debug-completion.md)及 [Infer 报告](../experiments/2026-10-26-infer-summary/README.md)。真实 C++ 的 PySVF 在 PAG 前置阶段触及 13 GiB；真实 Infer 两次捕获在 `AtomicExpr` 翻译失败；小型准入题通过不能据此认定已获得真实项目的精细分析能力。

项目覆盖、分析精度、离线索引和 AI 每次接收的信息量分别计量。基础地图应保存全项目发现、可复用关系、条件和缺口；需要精细别名或值流的问题再调用现成原生引擎，并复用结果。超时和不支持项要指向具体源码及缺失能力。

该分层方式属于待核验的设计方向。现有数据尚未证明其能在既定预算内满足全部必需验收，也不能将减少 AI 返回量算成降低了原生分析成本。完整 C++ 全程序求解是否为某项用户任务所必需，应按该任务所需证据判定。

## 7. 验收应回答的问题

以下是后续设计核对和验收应回答的问题，本次未启动新实验，也未新增或降低 G01–G09 的通过条件。

1. **信息是否到位**：面对原始 issue 和当前 diff，AI 能否查到受影响对象、关系条件及具体证据缺口？结果能否回到同版本源码？新增代码是否进入查询？
2. **影响是否表达正确**：是否区分真实身份、条件候选、未知和预算截断？能否排除同名异实例及错误配置连接，并暴露未改动消费者的影响？
3. **验证是否适用**：编译、测试和运行结果是否对应候选版本、目标配置、数据和场景？未执行项是否明确呈现？
4. **成本是否可用**：分别记录原生分析、索引、查询、AI 用时和 token；默认结果可以继续展开，分析失败有明确状态。
5. **AI 是否少引入问题**：在冻结的同题、同模型、同环境和预算下比较修复成功、新增回归及成本，保留无收益和负收益结果。

工程门槛与 AI 效果分别验收。依据既有协议，G01–G08 通过后再启动正式 G09；本次复盘没有授权新的验证或规则调整。

历史资产继续作为后续独立变量：先比较源码与源码＋工具，再研究加入历史资产的变化。此次阅读 #655 历史资产实验用于复盘，没有将资产接入工具。该案例和已读归因材料须登记为已见信息；24＋7 条是 31 条材料，相关家族及既有[样本划分](../datasets/msinsight-regressions/split.md)继续有效。
