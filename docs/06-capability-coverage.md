# 能力架构与覆盖清单

本清单把项目理解工具的能力类别与当前实现分开。P1–P5 在选定链路上验收；P7 加入全仓预检，避免把局部验收结果误读为全仓覆盖。

设计基线已经列出三个视图，但此前实施缺少逐项连接“机制类别—现有工具—适配—测试—覆盖缺口”的清单。沿首链逐段实现，使跨模块差异在 P7 才集中暴露。今后新仓库和扩展范围先跑预检，再选代表链和反例。

## 系统应有的组成部分

| 部分 | 输入与职责 | 交付与验证 |
|---|---|---|
| 仓库发现与覆盖管理 | 所有受版本控制路径、语言、包、入口、构建与配置 | 每部分都有已解析/候选/未展开/失败状态；未进入图的内容也能找到 |
| 语言事实提取 | 定义、引用、导入、类型、调用位置、继承与覆盖 | 身份有作用域，动态或歧义目标保留候选 |
| 跨边界连接 | 协议、路由、注册表、事件、插件、FFI、外部进程 | 自动提取两端身份、消息键、服务与实例条件；不按同名全局合并 |
| 数据与状态关系 | 参数、返回对象、字段、序列化、数据库、缓存、UI 状态 | 数据生产到消费及反查；区分调用关系、值来源和可能共享资源 |
| 时序与生命周期 | 异步任务、取消、超时、重试、锁、对象创建/清理 | 静态条件与运行事件分开；时序、原子性、占用需要对应证据 |
| 版本与变更维护 | 源码、构建/配置、规则版本、增删改名 | 新快照、失效关系、候选影响；旧验证不自动继承 |
| 运行采集与因果关联 | 用户场景、线程/进程、请求身份、状态采用与丢弃 | 可映射到静态图的执行记录；未采集和未执行分别表达 |
| 行为审查与断言 | 场景预期、正常/异常/并发与故障注入 | 根据独立预期验证结果；不能仅因执行路径不同判错 |
| 历史资产关联 | 外部问题、契约、修订、适用范围 | P6 负责接入；当前明确未连接 |
| 地图与查询 | 上述同版本事实、证据和缺口 | 概览、正反向、影响、解释、资产、运行及覆盖查询 |
| 评估与扩展 | 机制正反例、跨模块留出链、固定 AI 任务 | 保留首轮失败；新增机制同时回归其他写法和隔离反例 |

这是一份可扩展的能力分类。对特定语言、框架或项目的完整支持，需要对应适配与覆盖证据。

## 与已有工具研究的对应

以下沿用固定版本的[工具调查](../research/tools.md)与[实验记录](../research/experiments/2026-10-23.md)，不把文档声明升级成实测结果。

| 已调查方向 | 在架构中的位置 | 研究已确认的缺口 |
|---|---|---|
| CGC、CBM、CodeGraph、RepoGraph | 符号/引用、局部调用、存储与导航 | 自定义跨语言协议和业务数据流需要机制适配；各原版还存在语言或身份缺口 |
| code-map、Noir、MetaCall meta-ast | 接口发现与特定跨边界机制 | 支持范围依赖语言/框架；不能等同任意协议连接；后两者仍主要是文档调查 |
| RPG / CoderMind | 功能组织、职责总结和代码绑定 | 完整 LLM 地图未验收；语义摘要不代替可追溯的确定性连接 |
| Code-Craft | 论文候选 | 官方实现与版本尚未核实，不给实现能力评分 |
| OpenTelemetry、Jaeger、Playwright | 运行采集、传播、查询和交互场景 | 接入与业务断言仍需工程工作；P5 实际采用的采集/场景方案见其报告 |

工具选型继续以现有 CGC/Kuzu 加机制适配为主。覆盖矩阵决定下一步要验证哪类缺口，避免只因某个案例碰到问题才临时决定系统应有哪些部分。

## 后续准入规则

1. 新版本先更新全仓结构、语言和机制候选清单，显示与上版的新增范围。
2. 每新增一种机制，登记规则、来源、条件、正反例和代表性的不同写法。
3. 选择跨模块链检验组合效果；首次失败保留，不覆盖为最终成功。
4. 运行、资源和全仓完整性分别验收。三条静态链通过不替代这些验收。

实现与使用方式见 [P7 入口](../experiments/2026-10-24-p7/README.md)。
