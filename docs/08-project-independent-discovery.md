# 项目扩展与自动发现

工具按语言和技术机制提取关系。项目名、模块名、协议值、路由名和数据库名来自当前源码；Insight 是第一套真实验收对象。

## 新增模块后的行为

| 变更 | 工具应执行的动作 |
|---|---|
| 增加现有语言/机制的模块 | 重新发现源码、包/构建清单、入口和导出；提取事实，连接消费端与提供端 |
| 模块改名或迁移目录 | 重新计算身份、导入、配置与上下游；移除旧快照中的过期实体和连接 |
| 修改共享接口或配置 | 重新计算未改动消费者的连接和条件，保留具体未匹配位置 |
| 删除模块或接口 | 删除旧实体和连接；仍有调用方时报告未匹配关系 |
| 引入新运行语言 | 登记源码范围、位置及语义适配缺口，要求相应语言验收 |
| 引入新框架或通信机制 | 保存交互来源与现有提取状态，增加机制适配及独立正反例 |

覆盖状态与版本新鲜度独立。新版本的账本可以已经更新，同时仍有必需机制未验收。旧运行记录保留原源码和配置身份，新模块需要自己的适用场景证据。

## 通用引擎与验收材料

生产模块发现使用跟踪文件、构建清单、包声明、程序入口、公开导出、语言包和 Worker 入口等源码依据。目录约定是一种提示；不同布局下的入口与导出也应被发现。

连接适配按技术机制组织，例如 ESM/CommonJS、Python 包导入、Rust module/use/cfg、WebSocket、Worker、进程、文件和插件注册。接口名称和端点值由源码表达式、配置及值来源提供。支持一种新机制需要增加通用适配；增加使用已有机制的业务模块应由现有适配处理。

人工审计保存于独立评测目录，用于检验范围、方向、条件和误连。生成器不读取这些模块名单和端点答案。评测项目新增后，生产规则无需加入项目名称。

## 本轮已经执行的检查

[模块发现测试](../tests/test_project_inventory.py)使用独立构造的仓库，检查常见多包布局、任意目录中的入口/公开导出，以及新增、改名、删除模块。新增 Go 模块会自动成为必需语言缺口。构建/部署脚本保留必需检查状态。

同一发现器已生成 Insight 的版本化账本，并由[独立来源检查](../experiments/2026-10-25-w0/README.md)核对源码范围。该轮验证覆盖模块发现；语义连接、全量更新与安装后查询分别按 G02/G03/G07/G08 继续验收。
