# 研究决策与待确认事项

日期：2026-10-23。设计范围已形成 [v0.1 基线](05-design-baseline.md)，实施顺序见 [研究计划](../plans/README.md)和 [详细计划书](../plans/implementation-plan.md)。下面保留技术决策与依赖，不代表已完成实现。

## 已确定的范围

- 三个视图：项目地图、代码/接口/数据关系图、运行行为与证据。
- 历史问题资产与契约库由其他工作维护，本研究负责只读接入、技术关联、适用性和验证结果回链。
- 版本、来源、条件、歧义与覆盖缺口贯穿全部视图。
- 先以 unit/flows 验证闭环，再扩展两条真实链路，不先承诺任意项目的完整恢复。

## 先回答六个问题

1. Insight 的业务接口清单能否从 TS 请求和 C++ 注册两端分别自动提取？
2. 已有工具是否支持扩展这类提取器，而无需修改核心存储？
3. 统一接口身份如何避免同命令、同路径、不同服务之间的误合并？
4. C++ 数据库接口和候选实现能否可靠关联？需要哪些构建信息？
5. `unit/flows` 的结果如何返回并影响前端状态？哪些分支未核实？
6. 如何用一个受控场景验证迟到响应，同时关联静态与动态证据？

同时推进三个前置条件：真实 Insight 的运行环境与最小数据；资产库交换格式和真实样例；跨版本符号/接口的身份与失效策略。没有这些输入时仍可继续独立静态研究，相应集成验收保持待执行。

## 决策门槛

| 决策 | 所需证据 | 当前结论 |
|---|---|---|
| 选择代码索引底座 | 真实链路、证据、更新、覆盖诊断 | 尚未确定；CBM 只是导航候选 |
| 选择接口关联底座 | 提供/消费提取、上下文匹配、歧义处理 | CodeGraph/code-map 已实测，均未通过 Insight；有服务身份与方向缺口 |
| 接入功能职责层 | 有代码绑定的真实 LLM 生成与更新验证 | CoderMind 尚未通过 |
| 接入动态追踪 | 一个场景跨层关联、状态决定和断言 | 尚未接入 |
| 接入历史问题与契约 | 真实资产、稳定引用、适用条件、双向定位与悬空诊断 | 设计边界已确定，格式与真实资产待对接 |

## 下一步产物

- 固定工具提交、配置、输入范围和许可证清单。
- 一个小范围、可重复的 `unit/flows` 静态端到端实验。
- 未解析关系与原因清单，而非补猜出来的完整图。
- 自动更新中的新增、删除、重命名和协议值变化验证。
- 一个“查询 → 切换项目 → 旧响应返回”的动态场景。

CodeGraph/code-map 的本轮原版试验及复现材料已完成，见 [结果](../experiments/2026-10-23-unit-flows/README.md)。下一轮应优先验证可靠 C++ 事实层与项目协议提取扩展入口，再决定是否做小适配，不先投入大规模改造。

先检验可复用能力，再决定项目适配。不要把概念设计扩展成一套尚无验收依据的新平台。

阶段完成以 [验收矩阵](../plans/acceptance-matrix.md) 为准；未测能力不因计划已编写而变为通过。
