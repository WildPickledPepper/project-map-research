# 原生预算诊断第一批结果

日期：2026-10-26。状态：[计划 4.1](../../plans/semantic-impact-execution-plan.md)诊断交付完成；真实全程序数据流未通过。证据为研究提交 `49d28a2` 的[实际 CI 执行](https://github.com/WildPickledPepper/project-map-research/actions/runs/40339369105)及[脱敏收据](evidence.json)，原始输出保存在 Git 外的 D 盘结果目录。

## 1. 路线与成本结论

**同一次原生求解可以导出 SVFG 和 points-to，现有重复求解可以删除。** PySVF `1.0.0.50` 实际接受 `buildSVFModule(['-svfg', '-write-ander=…', bitcode])`，上游求解器写出关系，导出器从同一个活 PAG 核对两端身份。原有六项值流查询全部通过；三个独立全局对象指向检查全部通过，两个别名共享对象，独立对象没有误合并。

**当前 PySVF 路径的真实 C++ 成本在 PAG 构建阶段已超预算。** 复用 411 个编译单元生成、经 LLVM O1 处理的 163,765,192 字节输入；`get_svfir` 尚未返回时，进程树 RSS 达 13,961,203,712 字节，68.026 秒触发 13 GiB 上限并停止。日志只有 `pag_start`，没有 `pag_complete` 和 `pta_start`；因此本次尚未运行 Andersen，也未运行 MemorySSA/SVFG。完整构图按规则跳过，没有再启动同一大输入。

| 检查 | 实测结果 | 解释 |
|---|---|---|
| 实际 API | `get_svfir`、`run_pta`、`get_pta`、`getPAG`、`getSVFG` 可调用 | 已执行包支持分开的 PAG/PTA 调用 |
| PTA 返回对象 | `AndersenWaveDiff`，公开方法只有 `analyze` | stub 中的 `AndersenBase.getPts` 不代表返回对象可调用该方法 |
| 同进程上游文本导出 | 六项值流 6/6；对象身份 3/3 | 所有非空指向关系端点在当前 PAG 核对后才允许导入 |
| 小题 PAG | 调用约 0.0059 秒 | 只用于接口可执行性，不代表大程序成本 |
| 小题 PTA | 调用约 0.0006 秒 | 实际运行，和 PAG 独立计时 |
| 真实输入 PAG | 超 13 GiB 停止 | 当前路径无法在现有预算内建立基础表示 |
| 真实输入 PTA / MemorySSA / SVFG | 未执行 | 前置失败，无对应峰值或耗时结论 |

PySVF 的 `get_svfir` 组合 LLVM 模块读取与 SVFIR 构建；内部哪部分占主导尚未单独测量。该便利接口源码还设置常量/数组建模，不能将本次结果直接归因到原先 CLI 的具体阶段或断言两者使用完全相同默认模型。消除顺序重复求解改善总工作量；本次没有证据表明它降低了单次构图峰值。

资源每 0.1 秒采样进程树 RSS，事件另记内核自身峰值。小题在两个采样间隔内结束，采样峰值低于实际：例如导出题树采样约 7.8 MB，末事件记录自身内核峰值 50,896 KiB；报告保留两个口径，不用低采样值宣称内存收益。真实超限结果是观测到的下界，未测完成所需峰值。

## 2. 代码交付与验证

- [导出器](../../adapters/svf_export.py)增加显式同进程路径，复用上游文本格式；验证活 PAG 端点，格式损坏/缺端点直接失败。外部 CLI 文件保留跨进程未验证状态。
- Cargo 捕获分析、CMake 原生分析和旧重放入口改为单次 Python 原生求解/导出，删除前置 CLI 再求解。该调用路径在 C++ 独立题已实测；本批未重新执行 Rust 或真实全仓捕获，也未发布新的产品快照。
- 新诊断复用 psutil 记录进程树资源和阶段；本地执行超时/子进程停止 smoke，0.547 秒按预算结束。
- 本地原生边界/导出检查 18 项通过；完整 Python 回归执行 766 项、含 2 项跳过，336.938 秒，结果通过。文档链接与差异检查通过。原始失败与首次资源结果保留。

本批准入的是单次求解/同进程身份导出方法。旧的 4 GB 统一图仍保留原导入状态，其 points-to 不会因新方法准入而自动变成已验证。
