## 模式与边界

平台矩阵展开三个 OS、debug/release、default feature 开/关及 http feature 开/关，共 24 项；Linux 使用独立 Cargo 清单。所有组合先保留，后续在构建和运行中验证；需要排除或合并的组合按冻结规则提交源码或等价依据。

容器义务覆盖两类镜像、HTTP/mTLS、显式/分配端口，以及部分证书配置分支。启动器另展开 http/mtls/auto、证书缺失/完整/无效及端口选择，检查启动器端口和容器实际 TLS 模式是否一致。代理保留 HTTP 和 WebSocket 两种流程，JupyterLab 保留实际扩展入口和声明但未解析的控制台入口。数据/构建工具保留输入、失败、输出与清理义务；纯库和前后端子组件通过实际消费者场景验证。

[边界参考](boundary-reference.json)分别固定消费/提供来源、连接预期、身份/作用域负例和运行验证方式。它们是独立评测要求。8,150 个信号继续用于来源处置，语义边界身份在 W1/W2 中细化并记录分母修订；参考召回与来源处置分别计算。

两个依赖问题为 Rust 无界面启动引用的 `start_script.py`，以及 Jupyter `console_scripts` 声明的 `application:main`。固定提交中未找到对应目标路径，后续须追查生成/打包来源；这里没有将它们删除或当作已运行成功。
