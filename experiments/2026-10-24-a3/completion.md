- **按需展开**：入口正查、符号与资源反查、指定目标的证据路径、邻接分页、字段和状态检索。节点、关系、条件、源码证据、提供方和诊断均可逐层读取。
- **查询控制**：快照/导航版本/过滤条件绑定的续页游标；节点、检查边、深度、时间和输出预算。预算中断与未知匹配分开显示。
- **源码导航**：从索引对应的 Git 提交读取代码，工作区修改不参与；自建仓库测试已验证这一点。

## 成本与首轮问题

[旧 P7 入口实测](evidence/baseline.json)载入约 795 MB 图需要 7.61 秒，建立邻接索引 0.922 秒；查询后工作集约 2.59 GiB。

[最终索引实测](evidence/cost.json)构建总耗时 44.05 秒，含原始 JSON 载入、自动发现、校验、落库及采样开销；内部建索引阶段 27.28 秒。采样构建进程树工作集峰值约 4.00 GiB，设置 120 秒/6 GiB 外层预算。索引约 1.10 GiB，保存在研究 Git 外。这个一次性成本与查询成本分别记录。

每次查询启动新的 Python 进程，直接访问 SQLite；操作系统文件缓存未清空。七类耗时包含进程启动与采样，不能解释为冷磁盘性能。SQLite 缓存目标 8 MiB；查询采用访问量及输出限制控制对象规模，256 MiB 进程树外层预算只用于本次成本实验，不宣称为交互命令的 RSS 硬限制。

[首轮成本](evidence/cost-first.json)显示普通展开触发 3 秒时间预算。查询计划选择按 snapshot/ordinal 扫描；补充按 source/target 与 ordinal 组合的索引后，同类正反向展开分别约 0.09 秒和 0.10 秒，结果保留深度范围标记。计时精度、分页验收脚本和本地 TypeScript 环境的首次问题也保存在[首轮记录](evidence/first-failures.json)。
