# A4 后的通用机制修正与复验

依据：[首轮报告](report.md)与[实际缺口](evidence/gap-evidence.json)。当前不调整冻结版成绩。修正针对语法和机制，业务名称仅出现在回归参考中。

| 优先级 | 工作 | 可复用实现 | 修正后的门槛 |
|---|---|---|---|
| R1 | 统一传输入口发现，并关联导出别名、工厂返回回调 | TypeScript 编译器调用身份、现有 socket_flow 与 protocol_flow | 直接发送进入候选清单；无法匹配也保留未知/未匹配；同一请求不重复计数，导出名和源节点均可定位 |
| R2 | 保留延迟/防抖包装器中的参数来源 | 现有源码解释器、闭包、回调和对象/键值关系 | 静态字面值沿保存与回调恢复，动态输入仍未知；改函数名、属性名和命令不改变机制识别 |
| R3 | 分析模板解码器和 JsonResponse 分派 | C++ ValueTypes、协议注册与源码候选框架 | 从模板实参恢复具体请求类型及字段身份；无上下文时输出诊断；相同命令不同作用域继续隔离 |
| R4 | 补齐响应序列化与集合投影到消费者 | 现有 response/return/frontend 关系和 TypeScript 字段读写 | 具体响应字段连接到实际更新位置；区分数组方法与 JSON 字段、状态重置与请求结果采用、helper 返回与 Worker 转交 |

R3/R4 的精确根因尚需最小机制控制定位；首轮输出中的“提供方为零”“字段关系缺失”“映射后状态未连接”是已执行事实，表内实现工作是待验证方案。

## 每项实施顺序

1. 固定冻结版失败输入与输出，以自编名称建立最小正反例；不把答案写入提取配置。
2. 只修改对应通用规则，覆盖改名、跨文件、同名异作用域、动态值和预算截断。
3. 回归旧三条链、六项新模块材料、直接 socket 新增/删除及刷新失败恢复，单独报告修正后的开发回归成绩。
4. 检查全仓接口分母、重复候选、误连及未知状态变化；重新构建并验证内容一致。
5. 在新的模块/链参考冻结后执行下一轮规则留出。已用于修正的本轮材料不继续记为新的独立验证。

## 交付方式

保持当前事实层、SQLite/Kuzu 适配和查询入口，按机制提交小改动。每项附来源、诊断、首次失败、修正后结果及剩余未知。待这些静态门槛复验后，再扩展 A5 的新链运行场景。
